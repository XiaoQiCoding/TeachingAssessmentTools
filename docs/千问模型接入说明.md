# 千问模型选项

两个模块均提供“分析模型”选择：千问 Flash（qwen3.8-flash，首次默认）、千问 Max（qwen3.8-max）、千问 Plus（qwen3.7-plus）和 MiniMax M3。浏览器记住选择并在两个模块间同步；正在分析时不允许切换。已有正式证据与历史报告保留，切换只影响后续请求，不自动重跑已完成片段。

## 配置与重启

后端读取三个千问配置项：

```dotenv
DEFAULT_AI_MODEL=qwen3.8-flash
QWEN_API_KEY=填写千问密钥
QWEN_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
```

也可将接口改为配套业务空间的专属地址。MiniMax 的 MINIMAX_API_KEY、MINIMAX_API_BASE、MINIMAX_ANTHROPIC_BASE 继续独立保留。不会把某家的密钥发给另一家，也不会在所选模型缺少密钥时偷偷切换模型。

本地 `.env.local` 已沿用用户提供的密钥和 Token Plan 地址用于本次交互验证，该文件被 Git 和 Docker 构建忽略。阿里云说明 Token Plan 仅供 AI 工具交互式使用；正式网站后端部署应使用配套按量付费 Key 与地址。服务器环境变量需要另行设置，代码不会将本地密钥打入部署包。

本地重启使用项目根目录 start-local.bat，它会重新构建。容器部署需要重新构建镜像并传入环境变量；仅重启旧镜像不会更新代码。配置示例见 webapp/.env.example。

## 分析链路

- 所选模型用于连接预检、教案提取、观察条件生成、文字稿辅助定位、图片与视频候选分析，以及模块 A 的材料评估。
- 千问统一走 OpenAI 兼容接口；文字禁用额外思考；图片使用 image_url，视频使用 video_url，按2帧/秒输入。
- MiniMax 保留原有文字和 Anthropic 视频接口。
- 可选音轨转写仍是独立的 MiniMax ASR 服务，授权文字已单独说明。切换到千问不会把千问密钥用于 ASR。
- 当前千问视频分析仅认定视觉证据，明确标注声音和节奏正确性未核实。拍手动作不等于节奏正确；字幕只能辅助定位。
- 教案与定位的分批缓存按模型隔离；候选、已确认事件和报告证据保留实际模型来源。

## 验证

离线运行 npm run validate 与 npm test，覆盖模型默认值、切换记忆、请求路由、独立密钥、图片/视频格式、忙碌时禁止切换及旧 MiniMax 接口兼容。

显式真实集成测试：从 webapp 运行 npm run test:live:integration -- --model qwen3.8-flash。以《小青蛙找家》的原教案及已准备的60秒视频，直接经过应用处理链路；输出在 outputs/model-integration。需要先完成真实千问诊断以准备已知案例切片。模块 A 可增加 --module-a-only。测试会发送真实模型请求并消耗用量，不纳入默认离线测试。

接口连接、结构校验通过不代表课堂识别与评分准确性已完成验收，正式结论仍需回放核对。
