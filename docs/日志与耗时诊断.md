# 日志与耗时诊断

后续已增加可选完整检查与默认快速分析，初筛/精看及token统计规则见 [长视频快速分析](长视频快速分析.md)。下文60秒分段说明针对连续片段和完整检查。

## 页面查看

两个模块都有“运行诊断与日志”，可下载本页步骤记录。课堂时间轴中的“查看失败原因与耗时”提供失败阶段、上游状态码、服务商错误码、经过脱敏的原始说明、诊断编号和上游请求编号。点击“下载此请求日志”可取得相同诊断编号的服务器及浏览器事件。

旧片段没有记录过的原始错误和耗时无法追补，页面会明确标注。继续分析只重试未完成的片段，已有正式证据和成功结果保留。

## 每段耗时

- 原视频上传：原文件通过流式上传写入本服务的临时目录，同一页面会话只上传一次；后续片段及重试复用，显示0秒。上传阶段尚未请求模型。
- 片段请求与后台处理合计：只发送源视频随机编号及时间范围，从请求到取得完整JSON，包括网络、服务器切片、模型接口和结果校验。
- 服务器切片：FFmpeg 从源文件直接定位、截取并编码为MP4，保留音轨（若存在），不需要浏览器播放或录制，不再重复转码。
- 旧流程本机准备及转码：仅展示历史计时。主分析已不使用浏览器 MediaRecorder。
- 模型接口往返：发送给服务商直至收到模型响应，含服务商处理及服务器到服务商的网络，不能进一步等同为纯模型计算。
- 结果校验：解析模型返回并检查候选结构。

切片、模型往返和校验是后台处理中的分项，不能与请求总耗时再相加。原视频上传加片段请求为这一尝试的主要总耗时。每个片段累计重试耗时，另保留最近5次尝试的明细。没有计时的历史尝试不计入新统计，也不填成0秒。

当前是“原视频上传一次→服务器逐段切片→模型→校验”。按用户要求，本次仅替换切片机制，分段长度仍保持60秒、边界重叠5秒，五分钟分段另行评估。已有成功片段不会重跑。

## 临时视频管理

仅 Node 本地/容器服务支持直接切片。`POST /api/classroom/video-source` 接收原文件二进制流（最多512MB），验证视频及真实时长后返回随机编号，不返回本机路径。后续 `/api/classroom/video-candidates` 使用 `video_source_id`、`clip_offset`、`duration`。用户不能通过接口指定文件路径。

临时源文件位于系统临时目录 `teaching-video-sources`；闲置6小时后定时清理，单次切片临时MP4在请求结束后删除。服务关闭期间无法执行定时清理，下次服务启动/使用时清理过期目录。总临时源文件上限2GB，最多同时切片2个，编码使用2线程。原视频不会公开为URL，原文件不作修改。服务器重启或临时源过期返回410，页面清除缓存编号，下次重试重新上传；刷新页面也需要重新上传，但已完成结果仍保留。切片完成不代表已经人工核实。

`node tests/video-source-test.mjs --real-case` 可独立验证《小青蛙找家》的实际上传及切片，不发送模型请求。结果位于 `outputs/server-slicing/results.json`。本机实测260768786字节原视频上传1836毫秒，开头60秒切片3489毫秒，22:00起60秒切片3991毫秒；片段均保留可解码音轨与画面。这是本机实测，服务器性能和网络不同会影响耗时。

## 服务器日志

默认保存于项目根目录 `outputs/logs/evaluation-日期-序号.jsonl`，按UTC日期分文件，每份约5MB轮转，保留最近20份。通过 DIAGNOSTICS_DIR 可指定持久化目录。容器部署应将该目录挂载为持久卷，否则替换容器可能丢失日志。

记录请求开始/结束、所选模型、请求大小、文档提取、视频素材处理、转码、每次模型请求、结果校验、固定规则评分，以及音轨提取和ASR分块过程。记录模型输入输出token数量及finish_reason时，仅保留数量和状态，不保留原始提示词或模型全文。

不记录密钥、Authorization、教案正文、视频内容或base64素材。服务商错误消息会脱敏、截断。日志写入失败不会中断模型分析；下载接口会显示存储错误，本页仍可导出浏览器记录。

没有提供公开的全量日志列表。按随机诊断编号查询单次请求；编号会随对应响应返回。浏览器提交的诊断事件限制体积、数量和频率，并仅保留允许的字段。诊断记录可能仍含课堂处理时间和错误信息，应按项目运行数据管理。
