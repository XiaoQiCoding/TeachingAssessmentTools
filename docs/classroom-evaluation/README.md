# 课堂实施效果评估模块开发文档

## 1. 模块用途

完整评估入口为 `http://127.0.0.1:4174/`，按原量表统一管理基础信息、模块 A、模块 B、模块 C 和综合结果。模块 A 上传教案、教具说明和实物照片后由 AI 生成 A1 至 A5 评分；本模块工作页 `http://127.0.0.1:4174/classroom` 由 AI 从课堂视频提取可追溯的时间戳证据，并生成 B1 至 B5 课堂实施效果评分建议。评委只做事实复核，不从头填写 A、B 评分表。

当前版本的核心原则：

- 教案负责生成“观察清单”，不直接证明课堂效果。
- 视频先在浏览器本机播放；评委勾选授权后，20MB 以内原视频或较大视频的关键帧会发送给 MiniMax M3。
- AI 只提取可观察事实，不根据面部表情推断学生内心情绪，也不做人脸身份识别。
- 证据不足时返回“证据不足”和空分，不把未知结果当成低分。
- 学生只使用 `S01`、`S02` 等匿名编号。

## 2. 评委操作流程

页面采用四步引导，一次只显示当前步骤：

1. **上传教案**：MiniMax M3 提取课程名称、可观察目标、课堂环节、关键指令、预期反应和迁移任务。评委只需核对摘要；详细字段默认折叠。
2. **选择视频**：选择本机课堂录像。页面生成浏览器对象地址用于播放，并提示将采用原视频还是关键帧分析。
3. **确认节点**：评委确认授权后启动 AI。系统生成带时间戳的候选节点；评委可播放片段、修改节点并勾选采用。AI 遗漏时再展开手工补充。
4. **查看报告**：服务端根据已确认事件执行固定规则，按原量表列出 B1 至 B5 的指标描述、权重、1 至 5 分、客观证据、修改意见和加权得分。报告可打印、下载 JSON，也可下载为 Excel。

页面会在本机浏览器中自动暂存教案观察计划、AI 候选节点、评委已确认的正式证据和报告。切换到其他功能模块或误关页面后，24 小时内再次进入课堂评估会自动恢复。出于浏览器安全限制，视频文件本身不会保存；恢复后只需重新选择原视频，即可继续核对原来的节点和证据。需要开始全新评估时，点击页面顶部的“清空本次记录”。

## 3. 一键启动

在项目根目录双击 `start-local.bat`。启动脚本会：

1. 检查 Node.js；
2. 重新构建网站；
3. 关闭本项目占用 4174 端口的旧服务；
4. 启动更新后的本地服务；
5. 自动打开完整评估页面。

服务运行期间不要关闭“教学评估工具服务”窗口。需要停止服务时，关闭该窗口即可。

也可以在 `webapp` 目录手工运行：

```powershell
pnpm run validate
pnpm test
pnpm start
```

## 4. 模型配置

本机配置文件为 `webapp/.env.local`，它已被 Git 忽略。示例见 `webapp/.env.example`：

```dotenv
MINIMAX_API_KEY=填写中国版 Token Plan 密钥
MINIMAX_MODEL=MiniMax-M3
MINIMAX_API_BASE=https://api.minimaxi.com/v1
```

配置读取顺序为 `webapp/.env.local`、`webapp/.env`、项目根目录 `.env.local`、项目根目录 `.env`。已经存在的系统环境变量优先，不会被文件覆盖。

MiniMax M3 用于教案结构化提取和视频候选证据提取。报告评分仍由本地固定规则生成，不依赖模型，因此模型暂时不可用时仍可手工补充事件并生成规则报告。

## 6. 接口说明

### `POST /api/classroom/plan`

请求类型：`multipart/form-data`。

字段：

- `lesson_plan`：DOC、DOCX、PPTX、TXT 或 Markdown 教案。

返回内容包括：课程名称、目标、课堂步骤、教师指令、预期学生反应和迁移任务。接口先解析文档文本，再交给 MiniMax M3 结构化；浏览器不直接接触密钥。

### `POST /api/classroom/report`

请求类型：`application/json`。

输入主要包括：

- `lesson`：课程名称；
- `students`：匿名学生编号及层级；
- `events`：评委确认的时间戳事件。

输出遵循 `webapp/shared/classroom.schema.json`，包括五个维度、量表指标、权重、评分或空分、加权得分、证据列表、修改意见和审计字段。

### `POST /api/classroom/export`

请求内容与课堂报告接口相同，返回可直接用 Excel 打开的 `.xlsx` 文件。工作簿包含“模块B评估”和“课堂证据”两个工作表，便于评估人复核评分来源。

### `POST /api/classroom/video-candidates`

请求类型：`multipart/form-data`。`mode=video` 时接收不超过 20MB 的 MP4、WebM 或 MOV；`mode=frames` 时接收最多 36 张关键帧及 `frame_times`。接口通过 MiniMax M3 返回最多 30 个候选节点，所有节点初始 `confirmed=false`，必须由评委确认。

### `POST /api/evaluation/export`

接收当前完整评估记录及 `module=A|B|C|full`。可分别导出模块 A、模块 B、模块 C，或导出包含基础信息、三个模块、综合结果、签字、评分锚点和评估原则的完整 Excel 量表。

## 7. B1 至 B5 规则边界

| 维度 | 当前判定所需证据 |
| --- | --- |
| B1 课堂参与表现 | 至少 1 条教具使用中的参与、反应、操作或回避事实；有使用前记录时再加入前后比较 |
| B2 学习理解支持 | 至少 1 条指令后的反应或操作事实，评分结合完成结果与辅助程度 |
| B3 操作与分层适配 | 至少 1 条带完成结果和辅助等级的教具操作事实，并结合已选学生覆盖情况 |
| B4 技能习得与泛化 | 至少 1 条真实迁移任务事实；重复原任务不能证明泛化 |
| B5 情绪行为影响 | 至少 1 条教具使用中的可观察情绪或回避行为；有使用前记录时再加入前后比较 |

只要某维度存在直接课堂事实，就按本次表现给出 1 至 5 分和低、中、高置信度；样本数量不再作为“完全不评分”的硬门槛。没有任何对应事实时才使用 `insufficient_evidence` 和空分。每项按 12 分折算；存在空分时展示已评分权重内的加权小计，但不冒充完整的 60 分制模块 B 总分。

## 8. 数据与隐私

- 真实学生视频必须先取得学校审批和监护人书面授权。
- 视频使用本机 `blob:` 地址播放。只有评委主动勾选授权并点击分析后才会发送；短视频上传时审计字段 `video_uploaded=true`，关键帧模式保持 `false`。
- 完整评估记录写入当前浏览器的 `localStorage`，每套教具使用独立评估编号，可在页面顶部切换、新建和删除。保存基础信息、A/B/C 评分、文字证据、匿名课堂事件、综合结果和签字信息，不保存或复制视频文件。
- 模块 B 的工作暂存按评估编号隔离，默认 24 小时后失效；生成的模块 B 报告会同步回完整评估记录。
- 模型密钥只能位于后端环境变量或 `.env.local`，不得写入 HTML、测试文件或 Git。
- 测试材料不得包含真实姓名、人脸、联系方式、诊断编号等信息。
- 报告只引用评委确认的事件；模型建议不能替代评委最终判断。

## 9. 测试与修改检查

每次修改课堂模块后，在 `webapp` 目录执行：

```powershell
pnpm run validate
pnpm test
```

最低人工回归路径：

1. 上传一份匿名测试教案，确认摘要出现且下一步按钮启用；
2. 选择测试视频，确认第三步显示授权项和“开始 AI 提取”；
3. 验证候选节点默认未确认，勾选并采用后才进入正式证据；
4. 生成报告，确认 B1-B5 以量表表格显示，已有直接证据的维度给出 1 至 5 分、客观证据、修改意见和加权分；没有对应事实的维度保留空分；
5. 切换到“教具学具评估”再返回课堂模块，确认页面提示已恢复记录；重新选择同名视频后，原候选节点和正式证据仍存在；
6. 检查下载 JSON、下载 Excel 和打印功能；用 Excel 打开工作簿，确认“模块B评估”和“课堂证据”两个工作表均可读取。

## 10. 视频自动分析实现

当前已实现“AI 提候选、评委做确认”：短视频采用 M3 原生视频内容块，较大视频在浏览器按真实时长均匀抽取关键帧；请求同时包含教案目标、关键指令和视频真实时长。模型返回的节点不会直接写入正式证据，评委必须逐条播放、修改并勾选采用。审计字段记录分析模式、模型、候选数量和已确认 AI 节点。

下一阶段可增加音轨转写和分层二次扫描，以提升长视频中教师口头指令、短暂学生反应和稀疏事件的召回率。当前仍需用无隐私短视频继续验证不同编码格式、耗时和 Token Plan 配额。

## 11. 已知限制

- 当前关键帧模式不包含音轨转写，长视频中的短暂动作可能被采样遗漏。
- 浏览器会恢复结构化评估记录，但刷新、关闭页面或切换模块后必须重新选择本机视频文件；这是浏览器的安全限制。
- 暂存记录只保存在当前浏览器和当前访问地址中，更换浏览器、端口或电脑不会自动同步。
- 当前规则是可追溯的工程原型，尚未完成量表信效度验证。
- Token Plan 适合开发试用；多评委并发和正式生产部署需重新评估配额、限流、隐私与按量付费方案。
