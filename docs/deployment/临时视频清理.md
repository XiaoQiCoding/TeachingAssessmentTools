# 服务器部署：临时视频清理

## 为什么需要

课堂视频上传后保存在服务器的临时目录（默认 `/tmp/teaching-video-sources`），闲置 6 小时后应被删除。

服务自身在两种情况下会清理：下一次上传（`POST /api/classroom/video-source`）或查询容量（`GET /api/classroom/video-source`）。服务内部另有一个每分钟的定时器，但它被 `unref()` 了，服务进程停止后就不再运行。

因此如果服务长时间没有新上传，旧的视频会一直留在磁盘上，直到占用达到 15GB 上限，之后新的上传会开始返回 507。

独立的 systemd 定时器不依赖服务进程是否存活。

## 单元文件

- `webapp/deploy/systemd/teaching-video-cleanup.service`：单次执行的 oneshot 服务
- `webapp/deploy/systemd/teaching-video-cleanup.timer`：每 30 分钟触发一次，带 5 分钟随机延迟

## 安装

```bash
sudo install -m 644 webapp/deploy/systemd/teaching-video-cleanup.service /etc/systemd/system/
sudo install -m 644 webapp/deploy/systemd/teaching-video-cleanup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now teaching-video-cleanup.timer
```

确认：

```bash
systemctl list-timers teaching-video-cleanup.timer
sudo systemctl start teaching-video-cleanup.service   # 手动跑一次
journalctl -u teaching-video-cleanup.service -n 5
```

## 清理脚本

`webapp/tools/cleanup-video-sources.mjs` 的判定规则与服务内的 `cleanup()` 一致：

- 只处理符合 UUID 格式的源目录和 `transcript-*` 目录，根目录下的其他文件和未知目录名一律不动
- 依据目录修改时间判断过期，超过 TTL 才删除；正在切片或刚上传的目录 mtime 是新鲜的，不会被误删
- 输出 JSON，便于日志检索与监控

```bash
node tools/cleanup-video-sources.mjs --dry-run          # 只看会删什么
node tools/cleanup-video-sources.mjs --ttl-hours 2       # 临时改过期时间
```

环境变量：

- `VIDEO_SOURCE_DIR`：临时视频目录，默认 `/tmp/teaching-video-sources`
- `VIDEO_SOURCE_TTL_HOURS`：过期小时数，默认 `6`

## 注意

单元文件里的 `User=ubuntu`、`WorkingDirectory` 和 node 路径按当前服务器写死。换机器部署时需要改成实际路径；TTL 和目录则建议用上面的环境变量覆盖。
