# 真实案例验证流程

修改课堂分析后，模拟测试用于检查程序约束，真实案例测试用于检查当前接口是否可用及实际模型返回。两者分别报告，不能以模拟成功代替真实模型验收。

## 当前案例

- 教案：`test/《小青蛙找家》教学设计及反思.docx`
- 视频：`test/小青蛙找家上课视频.mp4`
- 案例原件只读；切片、原始模型返回、请求编号、耗时及报告保存到已忽略的 `outputs/live-diagnostics/`。

## 显式运行的真实测试

从 `webapp` 执行 `npm run test:live`，使用本地配置的 MiniMax 密钥，依次运行最小文字请求、原教案读取、第一批教案分析、5秒原生视频请求及60秒应用视频分析。会产生真实请求和相应模型用量，不加入默认离线测试。任一案例检查失败时返回非零退出码，不将未取得模型结果的案例标成通过。

对照模型连接测试可运行 `node tests/live-case-diagnostics.mjs --run-live --baseline-only MiniMax-M2.7`。该对照只验证文字连接，不代表其具备视频理解能力，不据此自动切换课堂视频模型。

如果最小文字和短视频都返回529，当前轮次停止进一步扩大到全课33段；先报告本账号当前服务路径的可用性问题及请求编号。接口恢复后，还需要以人工核对的真实任务片段检查识别内容是否准确，不能仅以HTTP成功判定模型质量合格。

## 页面提前检查

点击开始或继续分析后，先通过 `POST /api/classroom/model-readiness` 发送一次最小文字请求，最多等待15秒。无有效正文、服务过载、限流或鉴权失败时，不进入教案处理或视频录制，保留已有进度。该检查只证明文字连接，不保证音视频请求一定成功；实际视频仍单独检查。`GET /api/health` 仍只代表本地服务运行与密钥已配置，不能作为模型可用的证明。
